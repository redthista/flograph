# Changelog

## 0.1.10

| Category | Change | Details |
| --- | --- | --- |
| Feature | Nodes carry their own version number | Every builtin node now declares `NODE["version"]`, shown in the properties panel under the node's description and in the library tooltip before you drag one out. It answers the one question the app's version cannot: *is the node in front of me the one I just changed?* Two checkouts of flograph 0.1.10 both report 0.1.10, and a node file copied into a user-nodes folder reports the version of whatever flograph loads it — only a number living in the node's own source travels with the node and moves when the node moves. Everything starts at **1.0** except **Show Plotly** and **Chart per Value (Plotly)**, which are **2.0** after the rewrite above; a blank means the node predates this, which is itself the answer when an old build is what you are looking at. The key is optional and unknown NODE keys have always been ignored, so a versioned node file still loads on an older flograph. A test fails if a builtin has no version, so the mechanism cannot decay the first time someone adds a node and forgets. |
| Feature | Plotly Table and Plotly Style stand on their own | Both nodes now import nothing from flograph that they cannot do without, so either file can be copied into a user-nodes folder on an older flograph and will work there — verified by dropping both into a user-nodes directory with `core.plotly_spec` made unavailable, loading them and running them. The two helpers they needed are a six-line column splitter and a twelve-line number parser, which is a cheap price for a droppable file. The figure lock is the part that cannot simply be copied, because node scripts are executed in separate namespaces and a module-level lock in each would not mutually exclude — the very race it exists to stop. So they take flograph's own `FIGURE_LOCK` when there is one, and otherwise park a shared lock in `sys.modules`, which node namespaces do have in common; `setdefault` is atomic, so two nodes racing to create it still end up holding the same lock. **Show Plotly** and **Chart per Value (Plotly)** deliberately keep importing `core.plotly_spec`: they share a generated ~1000-line chart catalogue that the two of them must agree on, and duplicating it into both is worse than the module — the same call already made for `core/gantt.py` and `core/controls.py`. A test parses each node and fails on an unguarded `flograph` import, so the standalone two cannot quietly regrow a dependency. |
| Bug Fix | Plotly charts drawn side by side could fail with "Invalid value" | Node bodies share the process, so two chart nodes can be inside `px.bar()` at the same moment — and building a Plotly figure is not thread-safe. Plotly Express resolves an unset palette by reading the trace defaults off the **shared template singleton**, and stamping a theme onto a figure re-parents that same object, so one node's build corrupts the other's and plotly fails deep inside itself with a bare `ValueError: Invalid value` from `BaseFigure._index_is` — on whichever node happened to lose the race, which is why it looked random. It went unnoticed because no flow had ever had many chart nodes ready at once; the new chart-gallery example has eight, and failed two runs in five at the default worker count and none in three at a single worker. Figure construction now takes one shared lock (`core.plotly_spec.FIGURE_LOCK`), after which the same example ran ten times out of ten. A lock rather than `exclusive` — which is how the matplotlib nodes handle their own thread-unsafety — because the unsafe region is a few milliseconds of construction, not the whole node body: draining every other node in flight to draw a bar chart would cost far more than it saved. Chart per Value takes it per chart rather than per run, so a forty-chart split does not stall every other plotly node for the whole of it. A test sweeps the registry for nodes that build figures and fails if one does not take the lock, so a plotly node added later has to make the same call deliberately. |
| Feature | A **Plotly Table** node | Plotly Express has no table function, so a table drawn *as a Plotly figure* had no node. This one is built on `go.Table` and is deliberately not a chart kind: a table is headers and columns where every px chart is x and y, so folding it into the Kind dropdown would have meant a kind that ignored two-thirds of the settings around it. It is not the node for reading data — **Show Table** is far better at that, being a real paged viewer — it is for when a table has to *match* the charts beside it: same theme, same fonts, and it snapshots into a report or PDF exactly as a chart does. **Columns** picks and reorders, **Max rows** guards against carrying a million cells into the page, **Number format** takes a d3 format and applies it to the numeric columns only, and **Striped**, **Header fill**, **Row fill**, **Align**, **Row height** and **Font size** cover the look. It feeds **Plotly Style** like any other figure. |
| Example | Plotly Chart Gallery | New bundled example (**File ▸ Open Example ▸ Plotly Chart Gallery**): one table of hardware sales charted eight ways, a band per chart family, each with a note saying what to look at and which settings made it. Treemap and donut for the hierarchy and labels/values shapes that replace X and Y; box and histogram for the distribution settings; a scatter carrying size, colour and a facet per region; a plain bar wired into **Plotly Style** so both cards are on the canvas and the before and after can be compared at a glance; a **Plotly Table**; and a **Chart per Value (Plotly)** split three ways on a shared Y scale. The chart nodes ship with **More options** ticked so the settings the example used are visible in the panel rather than hidden behind the drawer. A dashboard page carries four of them. It is also the flow that exposed the figure-building race fixed above. |
| Feature | Show Plotly draws every chart Plotly Express has | The node offered seven chart types out of the forty Plotly Express draws. It now offers **twenty-eight** — everything except the ten map functions and `imshow` — grouped in the dropdown by family: line, scatter, bar, area, funnel and timeline; histogram, box, violin, strip, ecdf, density heatmap and density contour; pie, funnel area, sunburst, treemap and icicle; scatter matrix, parallel coordinates and parallel categories; 3D scatter and line, polar scatter, line and bar, and ternary scatter and line. With them come the arguments that go with each: **size, symbol, dash, pattern and text encodings**, **hover title and extras**, **facet rows and columns**, **animation frames**, **error bars**, **trendlines** (OLS, lowess, rolling, expanding, ewm) with a scope and a window, **marginal plots**, **bins, histfunc, histnorm and cumulative**, **points/notched/box** for the distribution charts, **line shape and markers**, **hole** for a donut, **branch values and depth** for a treemap, **orientation**, **log axes and pinned ranges**, **palettes and colour scales** with a range and midpoint, **opacity**, **theme**, an axis-renaming map and a subtitle. No chart shows a setting it cannot use: each row is gated on the chart kind, and the deeper two-thirds sit behind a **More options** tick, so a box plot never offers a bin count and a line chart is thirteen rows as before. The gating is not a hand-written list — `flograph/core/plotly_spec.py` carries a copy of plotly's own function signatures and derives from it both what each chart shows and what is passed to plotly, with a test that fails if the copy goes stale against the installed plotly. Settings that do not apply to the kind you switched to are kept rather than wiped, so switching back restores them, and the node's log names the ones it passed over. Two chart-drawing details changed with it: a chart left with no columns chosen fills the **x** axis rather than the y one for the distribution kinds, since a histogram of a column is what "histogram" means and filling y quietly made a two-dimensional one; and **Min/Max Y on a log axis now take the values you want to read off the axis** rather than their exponents, with a bound at or below zero refused by name instead of failing inside plotly with "math domain error". Existing graphs are unaffected: every previous setting keeps its name, its meaning and its default. |
| Feature | Chart per Value (Plotly) offers all of it too | Both Plotly nodes are now built from the same shared parameter set, so every chart type and every setting above appears on both and a chart type added to one cannot go missing from the other. Chart per Value keeps what is its own — Split by, Same Y scale, Max charts, and the cosmetic Columns/Rows/Fill — and keeps its own reading of **Min Y / Max Y**, where one end alone is a real thing to ask for because the other comes from the data; on Show Plotly the same two boxes are a plain axis range and need both. The shared scale now stands down for any chart with no column-based Y axis rather than for a hard-coded three, so a stack of pie charts or parallel coordinates is no longer bounded by a range that means nothing to it. A **Title** set on the node is kept in front of each panel's own heading (`Sales — region: north`), and the numeric column being split on is no longer charted against itself when the columns are left blank. |
| Feature | A **Plotly Style** node | A Viz node that takes a Plotly figure in and hands a restyled one out, splitting *what the chart shows* from *how it looks*. It works on any Plotly figure — Show Plotly, Chart per Value, the Gantt chart, or one built in a Python Script node — so styling can be added to a chart that already works without touching it, and a stack of figures is styled in one pass and stays a stack. Theme and palette; title, subtitle and title alignment; axis, legend and colour-bar titles; legend shown, hidden or moved, including four floating positions inside the plot that buy back the width a right-hand legend costs; hover mode including the unified ones; log axes and ranges; gridlines; d3 tick formats for numbers, percentages, money and dates; tick angle; category sorting, where "total descending" turns an unordered bar chart into a ranking; a range slider; a horizontal or vertical **reference line** with a label; a **note** in any corner; fonts, text colour, plot and card backgrounds and margins. Every setting has a **keep** position and that is the default, so the node is inert until asked and can be dropped in front of a figure somebody else built without flattening it. The input figure is never modified — the node styles a copy, because a node's output is cached and may be wired to several places at once. |
| Feature | The folder readers read a whole tree | **Search subfolders** walks everything below the chosen folder instead of just its top level, so a year of monthly exports filed under `2023/q1/…` reads as one table. It is on all four folder readers — **Read Excel (Folder)**, **Read CSV (Folder)**, **Read Parquet (Folder)** and **Read PDF (Folder)** — which share one discovery service, so they agree on exactly what a pattern means. **Include folders** and **Exclude folders** narrow the walk: comma-separated globs matched against a subfolder's path below the root (`2023/q1`) or its own name (`q1`), where include keeps only the folders that match and exclude drops a folder together with everything under it — pruned during the walk, so an excluded branch is never entered. Both are ignored while *Search subfolders* is off, so a rule left over from a recursive run cannot empty a flat read. **Add folder column** records which subfolder each row came from (`.` for the folder itself, otherwise `2023/q1`), sitting between *sheet* and *source_file* where those apply; Read PDF (Folder), whose tables always carry a `file` column, gains a `folder` column beside it whenever the walk is on. The file **include / exclude patterns** now also take a path: a pattern with a `/` in it (`2023/*.xlsx`) is matched against the file's path below the folder rather than its name. Files are still read in sorted order — now by relative path, so each subfolder's files stay together and a tree stacks the same way every run. |
| UI | Right-clicking the canvas opens the node palette | The canvas context menu was a tree of nested category submenus. It now opens the same searchable node popup a dropped wire uses, at the click position, and the chosen node lands where you clicked. Two non-node entries are kept as rows at the top — **Frame**, and **Paste** when the clipboard holds something — formatted like node rows (`Frame    (canvas)`). Selection starts on the first node, so Enter on an empty search still adds a node. The dropped-wire popup is unchanged and gains no extra rows. |

| Fix | The canvas is infinite again when the scroll bars are off | Fitting the scrollable span to the flow (added so the bars scroll at canvas speed) was applied unconditionally, and the view cannot scroll outside its `sceneRect` — so a drag pan hit a wall at the edge of the flow plus a margin, whether or not the bars were shown. The fit now follows the setting: bars on keeps the proportional fitted span, bars off (the default) goes back to a world-sized span so a pan is never blocked in any direction. Turning the bars on still bounds a drag pan to the fitted span — that is the span the bars represent. |
| Fix | A middle-drag pan no longer scrolls at the border, or sticks the grab cursor | Opening a flow replaced the graph out from under any drag or pan that happened to be live, so its mouse release never arrived: the edge-scroll timer stayed armed and the closed-hand cursor stuck, and the next plain middle-drag pan of the new flow crept at the viewport edge as though a node were being dragged there and would not let go. Replacing the graph now cancels any in-progress wire/node/frame drag and middle-drag pan first, and the edge-scroll tick ignores the border outright while a middle-drag pan is what is reaching it — a pan is its own way to the edge and was never meant to trigger the drag-to-the-border scroll. |
| Fix | Dragging a lone frame scrolls the canvas at the edge, like a node | Holding a node or a multi-frame selection against a viewport border glides the canvas that way (G3); a single frame carried its own move and skipped the machinery that starts the glide, so it alone stopped dead at the edge. It now holds the edge-scroll for the length of the drag and rides the pan with its contents. |
| Fix | An errored node in a "run on ask" frame shows the error, not the frame note | A node held by a frame set to run only when asked wears a "Held by its frame…" tooltip — which sat on top of the error message when that node failed during the frame's run, hiding the one thing worth reading. The error now takes the tooltip slot ahead of the frame-hold and manual notes (a padlock or a frozen badge still speaks first, since those stop the node running at all). |

Manual zoom and pan are disabled while it is on, and the zoom indicator says so. At a fitted zoom, painted content (KPIs, charts, PDF pages) re-renders crisply while raster widgets such as data tables and spreadsheets are scaled and read slightly softer. |

Bounds now use the recursive result only while it is plausible, otherwise counting the card's own children and skipping parked panels. The damage rect still covers every pin. |

| Feature | PDFs can be read, parsed and shown | Three new nodes with no new dependency, using the pdfium build Qt already ships: **Read PDF**, **Read PDF (Folder)** and **PDF Viewer**. None requires a QApplication, so they run on engine workers and in headless CLI runs. *Read PDF* returns one row per page (`page`, `label`, `text`, `characters`, `words`, `width_pt`, `height_pt`) plus a `document` port of metadata, so a PDF arrives as a table that Filter Rows, Group By and String Manipulation can already handle. *Read PDF (Folder)* stacks a directory with a `file` column and a second **documents** output listing title, page count and whether each file has a text layer; a password-protected or corrupt file is reported there with its `error` filled in rather than failing the read. *PDF Viewer* paints a page directly onto the canvas item and dashboard tiles at the size the card is drawn, so a long report costs one page of pixels and the file is read lazily. Dropping a `.pdf` on the canvas creates a viewer. Every node has a setting for how much of the document travels downstream: *Metadata only* (default) carries the path and never reads the whole file, *Metadata + bytes* adds `bytes` and a `data_uri` at the cost of caching the whole file. Scanned documents with no text layer are reported in the log rather than producing blank rows; OCR and table extraction are out of scope. New example: **18 PDF Documents**, which writes its own PDFs. |
| Fix | Dragging a node no longer leaves pin skids or ghost circles behind | Pins are drawn outside the node body (`PORT_EDGE_GAP`), but `NodeItem.boundingRect` covered only the body — so on the partial-update path a move damaged less than it repainted, leaving semi-circular skids along the drag path and ghost pins where a relayout had moved one. Offscreen tests repaint whole frames and never showed it. `boundingRect` now unions `childrenBoundingRect()`, and `_layout_ports` registers the old extent before pins move. |
| Fix | Wires follow rebuilt pins — and undoing a spare connect no longer grows ghosts | `NodeGraphScene._on_code_changed` re-aimed each wire's `src_port`/`dst_port` identity but not the anchors the wire draws through, so wires stayed pointed at PortItems the rebuild had removed and reported local coordinates near the node's top-left corner. `ConnectionItem.reattach` now moves identity and anchor together, leaving a collapsed frame's stand-in pin to the fold machinery. Three related fixes: undo/redo of a spare connect grew a new port each cycle (`ConnectCommand` now stores the resolved port name rather than the `"more"` slot it aimed at); ports rebuilt while zoomed out stayed visible (`rebuild_ports` now re-derives LOD/collapse visibility); and `adopt_extra_inputs` could list a grown port twice in `spec.inputs`, collapsing two pins into one dictionary slot and stranding the loser at the node origin. Regrowth now starts from the script's own ports, and `rebuild_ports` sweeps every pin child. |
| Feature | Concatenate stacks as many tables as you wire | Concatenate has *top*, *bottom*, and an always-empty slot at the bottom: wiring the empty slot adds a permanent port (`in3`, `in4`, …) and a fresh empty slot appears below it, so there is always exactly one invitation and no ceiling. Ports stay declared rather than data-derived — growth happens only when a wire lands, so a node's shape always matches its wires and can be read before it runs. The mechanism is graph-level and available to any node declaring a `spare` port: promotion lives in `Graph.connect` (a refused drag grows nothing), the grown list travels with the node instance through forks, saves and loads, undo of a connect leaves the empty slot in place, and the canvas is notified through the same `code_changed` event a fork uses. Existing flows are unaffected: *top* and *bottom* behave as before, intersection covers all connected tables, and the log reads `120 + 80 + 45 rows -> 245`. |
| Feature | The statistics window remembers between sittings | Run history was session-only, so reopening a project gave a blank statistics window until something ran. Each save now writes the bounded history (the existing "runs to remember" setting) into the cache side-car as `runs.json`, and opening loads it back into the timeline, both tables and the status bar's last-run readout. It lives in the side-car rather than the project file because it is derived data, and **Reset Caches** leaves it alone. A missing or corrupt file means no history rather than an error, a new project or example starts unmeasured, and records are plain scalars so old runs survive library changes. |
| Fix | Reopening a flow finds it the way it was left | Projects open lazily with cached nodes registered as spilled, but nothing notified a card when its value returned — so reopening showed placeholders: empty slicers, charts and web views at their run prompt, KPIs reading "None". Two changes fix it. `OutputCache.became_resident` now fires when a spilled entry becomes values again, and the window batches those arrivals (200 ms) into one refresh sweep across canvas cards and dashboard tiles, so a card heals whoever restored its value. And after registering, `_restore_cache` queues exactly the entries visible cards display — figures, webviews, table viewers, KPIs, slicers, controls, plus whatever feeds a slicer's or control's option list — through the engine's pool-thread warm (`warm_entries`), which follows alias chains to blob owners. Everything else stays on disk. Nothing re-runs, the graph stays clean, and a node whose blob has genuinely gone missing goes dirty rather than pretending otherwise. Older projects benefit wherever their saved fingerprints still match. |
| Feature | Saving shows its work, and a full disk says so | The cache side-car used to be pickled on the UI thread, freezing the window for seconds to minutes on a large flow. The project JSON still saves synchronously, but the side-car is written on a pool thread behind a second progress bar beside the status line — `Saving proj.flograph · cached results 12/40` — while editing and running continue. Planning the save (walking the graph, hashing fingerprints) stays on the GUI thread and hands the writer a snapshot of ids, entry objects, fingerprints and frozen flags, so the background half touches only the filesystem. Until it lands, a second Save (and Save As, before it moves the project) waits, starting a run is held off, and closing the window waits for the write so the manifest is not lost. A save that fails because the disk is full now reports "The disk holding … is full. Free some space … and try again." rather than a stack trace, with quota-full (`EDQUOT`) counted as full. An unreadable or unwritable individual blob still skips just that node. |
| Feature | Warns when the drive is running out | The resource monitor now watches free space on the drive holding the project, where the cache side-car grows, and warns once in the same amber as memory pressure when it falls below 1.5 GB: what is left, and the two remedies (**Reset Caches**, or save somewhere with room). It uses the same hysteresis as the memory warning, clears itself, carries onto the run line during a run, adds a free-space line to the monitor's tooltip, and stays quiet for an unsaved project. Free space is queried at the project's own folder so the kernel resolves the filesystem that actually holds it (`/home` as its own filesystem, as on immutable distros), with psutil backing up `shutil`; the tooltip names the mount point it used. A drive that cannot be read produces no warning. |
| Performance | Cache blobs are compressed on disk | Side-car blobs are now zlib-compressed at level 1, chosen by measurement: string-heavy frames drop to roughly 40% of raw for a few percent of the pickle time, float blocks barely shrink under any codec, and lzma's better ratio cost a 4× slower read on every open. Compression streams through the pickle rather than building the blob in memory first. The reader sniffs each blob (a pickle starts `0x80`, a zlib stream never does) rather than trusting the manifest, so raw, compressed and mixed directories all load with no migration step. **Settings › General › Saving › Compress cache** (on by default) turns it off; the change takes effect at the next save and rewrites nothing already on disk. The manifest is schema 3 and records each entry's codec and both sizes, tallied as the stream goes by, which the resource monitor's tooltip reports as `Cache on disk 412 MB · 1.02 GB uncompressed (41%)`. Older builds skip a schema-3 side-car cleanly. Stray `.pkl.tmp` files from an interrupted write are now swept. |
| Example | A tutorial for running a second flow while one is running | **File ▸ Open Example ▸ Run While Running** — two independent branches, each a slow script (progress on its LED, narration in the log) feeding a table. The canvas note walks through running Branch A with **Run To This Node**, then joining Branch B to the running plan the same way and watching them overlap in the statistics timeline. A third step joins mid-branch, where the joined node waits only on its in-flight ancestor, and a fourth covers **Cancel** stopping joined nodes too. |
| Feature | A run clicked while another is running joins it, and they run together | `run_targets` was a no-op while a run was in flight, so clicking Run during a run did nothing silently. **Run All, Run Selected, Run To This Node, a frame's ▶ and a node's right-click Run now join the running plan**, and their nodes start as soon as the pool has room. The plan is built exactly as for a fresh run — same closure, same flags, same manual-node rule with `asked` intact — then everything the current run already owns is removed and the remainder is seeded into the same readiness bookkeeping. A joined node whose ancestor is still in flight waits for it, and an upstream failure prunes it identically. The progress counter grows as joins land, the status bar reports **"N nodes joined the running plan"**, and joined nodes light up queued then running on the canvas. **Cancel** removes joined nodes along with planned ones. A run joined while spilled cache is still being read warms under its own generation, and dispatch is held until every warm is in. |
| UI | Show scroll bars on the canvas | **Settings › Canvas › Display › Show scroll bars** (off by default) turns on horizontal and vertical scroll bars that show where the viewport sits and drag to move. The span grows with the flow after a quarter-second delay, and panning past the edge stops the bars at the flow's bounds. Pan, wheel-zoom, edge-scroll and the minimap are unchanged. The setting applies to dashboard pages too. |
| Feature | Hold a wire, a node or a frame at the canvas edge and the view scrolls | Holding a drag against a viewport border pans the canvas that way, accelerating the further into the edge band the pointer goes. It works for a wire's free end, a node, a multi-node selection and a frame with its contents. What is being dragged follows the scroll rather than being left behind: a wire re-aims at ports as they pass under the cursor and keeps its connect-validity tint, and a dragged selection snaps and commits exactly as a manual drag would, with no jump on the next mouse move. |
| UI | A node's name in the statistics window is a jump | Every node name in the window is clickable — the Run tab's table and timeline, and the Graph tab's heaviest-nodes table — and clicking it selects the node and brings the canvas to it, zooming back in from far out. The click carries the node id rather than the label, so duplicate names and renames both resolve correctly. When a designer re-exports an SVG, element ids are renamed or dropped and the popups, stylesheet rules and anchors bound to them stop working. The flow inventories both files, matches element to element, reports which of the page's hooks survive, and writes the old ids back onto the new artwork. **Matching** runs best signal first — id, then `data-name`/`inkscape:label`, then geometry fingerprint, then text, then position — and a name mismatch vetoes the two weakest passes, so a room deleted and a different one drawn in its place is reported as *missing* rather than matched. Because a re-export commonly flattens shapes to `<path>` and discards ids, matching pairs on what an element is rather than which tag drew it, including a bounding-box pass that recognises the same rectangle however it was drawn; `d` is walked command by command rather than read as a flat list of numbers, since an arc's radii and flags are not coordinates. **The retrofit** hands the old ids back in a single pass, rewrites internal `url(#…)` references, restores classes the page uses, and carries every `data-*`, `aria-*`, `on*`, `title`, `role`, `tabindex` and `href` across — named by pattern rather than by list, since frameworks keep adding more — while leaving presentation (`fill`, `stroke`, `style`, `transform`) to the new artwork. Values are escaped on the way in. It writes an id only where the element can be identified uniquely in the raw markup by geometry plus transform and class as tie-breakers, declining and explaining when two identical paths are candidates; comments, CDATA, `<script>` and `<style>` are masked before any tag is counted. Ids are written whether or not the page was seen to use them, and classes are not: an unused id costs a few bytes, while restoring a class the old stylesheet still has a rule for changes how the drawing looks. **Coordinate systems need not match.** A drawing exported from one tool measured in thousands can come back measured in hundreds, which defeats every geometric pass and reports every element missing. The diff therefore fits the old artwork into the new one's space before comparing, taking the scale and offset that carry one extent onto the other and treating two axis ratios agreeing within a couple of percent as one number. That fit is scored by how many elements come to rest on an element of the new artwork and is applied only if it beats leaving well alone. Because extent-to-extent fitting fails when one file has a border rectangle the other lacks, the fit is also voted on: every pair of elements of similar proportions votes for the scale that would carry one onto the other, the majority scale wins, and the offset is voted the same way among pairs whose sizes then agree. Both fits are tried and scored, the better is used, and the log reports both. The bounding-box pass became a tolerance expressed as a percentage of the drawing rather than an exact key. When almost nothing of one drawing comes to rest on the other, the diff says so rather than reporting confidently — most often that means a Source File whose path is unset is reading its built-in sample. **Hook detection** covers three ways a page reaches into artwork. Ids: patterns find `getElementById("room-lab")`, a `#room-lab` rule or an `href="#room-lab"`, and wiring the old artwork into **HTML Hooks** additionally counts any string that is exactly the id of an element in the drawing, for pages that bind one handler and read `event.target.id`. The `.js` files a page loads are read too, resolved from beside the page (a root-absolute `/assets/app.js` tried against the page's folder, then the bare filename), scanned as an inline script is, and named in the `where` column; files that cannot be read are named in the log. Classes: a class the page uses is restored onto the matched element. Element types: `querySelectorAll("rect")` is as much a hook as an id and the one an export breaks most thoroughly, so type dependencies are found and checked against the new artwork's tag census; a comma is an *or*, so `#Boxes rect, #Boxes path` depends on neither type alone. **Groups and layers** get their ids back as well, since a page often scopes handlers to a layer. A `<g>` has no bounding box, so groups are matched by contents: the counterpart of a layer is the group holding the most of its matched contents and the least of anything else, and the `<svg>` itself is never the answer. A bare `<g>` is located in the markup by position — the nth `<g>` of the document — and only if the tag it lands on is as bare as the one it stands for. Where the export dissolved the layers entirely, the id goes on the innermost element that holds the layer's contents. A layer with nowhere to go is named in the log along with what it costs. **Verification** closes the loop: the retrofit reads the finished artwork back and reports how many of the ids and classes the page asks for actually exist in it (`2 of the 3 id(s) the page asks for now exist in the artwork — still missing: room-plant`), counted over ids the artwork itself once had. Beyond that, the page's own queries are run against the finished artwork and answered with what they return plus how many of those elements carry an id, `if (el.id)` being what the page tests. A query returning nothing is walked from the left to find the step that empties it, so the answer is `#Boxes matches 1 element, but nothing inside it is a rect` rather than a bare zero. Selectors that cannot be parsed — a pseudo-class, a sibling combinator — say so rather than guessing, and a query about the page's own furniture is left alone. **A Mapping table** sits in the middle of the flow and on the dashboard: every element of the new artwork beside the one it was paired with, in document order. Type an id into any row and that element gets it — matched or not, hooked or not — with `-` to leave one alone and anything untyped staying automatic. An element carries one id and an id lives on one element, so keying an id onto a row takes it off whatever row had it. It is an ordinary linked Table node, so typed values survive every re-run while the columns around them refresh. **Three live page previews** sit side by side on a **Before / After** dashboard — the original, the new artwork dropped straight in, and the same artwork after the retrofit. Page-borne SVG is rarely well-formed XML, so markup is repaired first and anything still unparseable is read with an HTML parser, both paths canonicalising names so a diff stays comparable. `<svg>` blocks are located by depth rather than by the first closing tag. A page whose CSS and JS live in separate files previews correctly: the prepared page carries a `<base>` at its real folder, and root-absolute asset URLs are repointed there when the file exists. Assets are not inlined, since that drops `defer` from a script tag and moves the script before the document, leaving every handler unbound. With no path set, the node names the external files it cannot find. The diff also reports when the two sides look like the same drawing, which usually means the page input is pointed at a file this flow has already written.
