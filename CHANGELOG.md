# Changelog

## 0.1.8

| Category | Change | Details |
| --- | --- | --- |
| Feature | Input controls: a new node category | A new **Input** category of nodes that are *controls* rather than transforms — you set their value, and everything downstream re-runs. **Slider** (int or float, with min/max/step/decimals and the number shown beside the track), **Number** (a spin box, with display-only prefix/suffix like £ or %), **Text** (single-line or multiline, committing when you leave the box so one edit is one undo step rather than one per keystroke), **Date** (a calendar picker emitting an ISO `YYYY-MM-DD` string, which pandas comparisons take directly, with optional earliest/latest bounds), **Toggle** (a tick box with your own label, emitting True/False) and **Choice** (a dropdown). Every one carries a **Caption** you write, so a dashboard reads as a form rather than a row of unlabelled widgets. Ports are properly typed — number, string, bool — so wires are validated as usual. Each control works identically on the model canvas and as a dashboard tile: the same widget, resizable, one undoable step per adjustment, and an automatic re-run of everything it feeds. Values are ordinary params, so they save with the project, undo, and survive a fork. The point is a dashboard you can hand to someone who will never open the model canvas: they turn the knobs, the charts answer. |
| Feature | `card: "control"` node contract | Input controls are a declared card kind, not six special cases. A node script says `"card": "control"` plus `"control": "slider"` (or `number`/`text`/`date`/`toggle`/`choice`) and one host renders it from that plus the node's own `PARAMS` — so the canvas card and the dashboard tile share a single widget and neither knows what a slider is. Adding a control node built on an existing shape is now a node script and nothing else. Like `card`, the shape lives in the script text, so it survives forking and saving; an unknown shape (a project written by a newer flograph) leaves the card empty rather than refusing to open. |
| Feature | Standalone Slicer, and a `selected` output | The Slicer's table input is now **optional**. With nothing wired in, type the values into the new "Values (one per line)" box and it becomes a plain value picker with no data behind it — and it needs no run to show them. Its `table` output is then a one-column table of whatever is ticked (named after "Column", or `value`), so an unconnected slicer is a source rather than a dead end. A second **`selected`** output carries the ticked values as a list in both modes, so one picker can drive the next: wire a Slicer's `selected` into a Choice node's `options` and the dropdown offers exactly what was ticked. A connected Slicer filters exactly as before. |
| Feature | Choice options from your data | A Choice control's dropdown fills from its typed-in list, or — when something is wired into its `options` input — from your data: a DataFrame contributes the unique values of the column you name (or its first), a Series its unique values, a list its entries. Options refresh on every run. A stored pick that is no longer offered stays visible and marked "(not in list)" rather than silently changing to something else underneath a dashboard, and nothing picked yet means the first option, which is what the dropdown is already showing. |
| Bug Fix | A slider drag re-ran the flow per pixel | Dragging a Slider committed on every tick of the handle, so one drag queued a downstream re-run for each pixel of travel — unusable over a heavy model — and pushed a separate undo step with each one, burying the undo stack. A drag now commits once, on release, with the value you actually let go on: one run, one undo step. The number under the handle still updates live as you drag, and a run finishing elsewhere mid-drag no longer snaps the handle back. Discrete changes (arrow keys, the wheel, clicking the groove) still commit immediately, having no later moment to wait for. |
| UI | Slider shows its range and its value in place | A Slider now labels both ends of its track — the minimum to the left, the maximum to the right — and the current value rides directly under the handle rather than sitting in a fixed corner. The scale is readable straight off the card, which matters most when the bounds are wired from data and nobody typed them. Both labels use the slider's own formatting, so decimals and thousands separators match the value. |
| Feature | Controls configure themselves from your data | Every input control has optional input ports for its own settings, so a dashboard's controls fit the data rather than constants somebody typed once. **Slider** and **Number** take `minimum`/`maximum`; **Date** takes `minimum`/`maximum` for its calendar; **Text** takes `placeholder`; **Toggle** takes `text` (its label); **Choice** takes `options`. Wire a column in and it's reduced for you — lowest value for `minimum`, highest for `maximum` — so one date column into both ports pins a picker to exactly the period your data covers. A wired setting wins over the typed one while connected, and unplugging restores what you typed. The chosen value is kept inside the live bounds, which is what makes a wired bound double as a sensible default: an untouched date picker with `maximum` wired lands on the latest date you actually have. Controls chain on their settings as well as their values — a Number can drive another control's maximum. Crucially the node's `run()` clamps exactly as the widget does, so the card and the flow can never show different numbers. |
| Feature | Control Template node | A new **Scripting > Control Template** node: a commented, working input control (a percentage slider that emits a fraction) to fork as a starting point for your own. It documents the whole contract — which widget shapes exist, which params each one reads, which input port names the host understands, and the one rule that matters: emit what the card is showing. Sits beside the existing Node Template. |
| UI | Toggle's tick box is visible when unticked | A Toggle drew nothing at all when off and a bare floating tick when on, because the platform's checkbox indicator vanishes against the dark card. The box is now drawn explicitly — an empty outlined square when off, a filled blue one with a tick when on — so it's obvious there's something there to click. |
| Feature | A list of charts renders as a stack — one chart per value | A node output that is a **list** now renders as a stack everywhere a single one would: scrollable on the canvas card, on a dashboard tile, and as a run of blocks in a report. That is all "the same chart, once per region" needs — the loop lives in the node's own code, so there is no faceting UI to learn and it isn't tied to one plotting library. Plotly lists become **one scrolling page** rather than one webview each, with plotly.js included once instead of per chart (~3 MB apiece). New **Viz > Chart per Value** node does it for you: pick the column to split on and it returns one chart per distinct value, on a shared Y scale so the panels can be compared by eye, with a "Max charts" guard so splitting on an id column by accident can't build thousands of figures. Fork it and the loop is yours. |
| Feature | Chart per Value, in Plotly too | **Viz > Chart per Value (Plotly)** is the interactive half of the node above: one Plotly chart per distinct value of a column, each with its own hover, zoom and pan, stacked on a webview card. The mechanism is not duplicated — both nodes just return a **list**, and the existing renderers already knew what to do with one; the only difference is what the list holds, matplotlib figures onto a figure card or Plotly figures into HTML. Same Split by / X / Y / Max charts settings, plus **Color by**, and the same `cosmetic` Columns / Rows / Fill so re-arranging a slow split doesn't re-run it. Seven kinds (line, bar, scatter, area, histogram, box, violin); the shared Y scale that lets panels be compared by eye is skipped for the three distribution kinds, whose value axis is a count or a spread the figure derives itself and would be cropped by bounding it. The whole stack is one document carrying plotly.js **once**, so twenty charts is ~5 MB rather than a 3 MB bundle apiece — which is why "Max charts" defaults lower here (20) than on the matplotlib node (40): the page size barely moves, but every chart is a live plot in the same document. A **Bar mode** setting — group, stack or overlay — lands on this node and on **Show Plotly** alike, read only by the bar and histogram kinds. Plotly Express stacks bars the moment a chart has more than one series, which is the wrong default for a panel whose whole purpose is comparing them, so **group** is the default here rather than Plotly's own stack; a saved graph from before the setting existed comes up grouped too. The shared Y scale knows about stacking on this node: a stacked trace reaches the row's total rather than its tallest column, so the axis is bounded by the row sums for **stack** bars and for **area**, which px.area stacks unconditionally — otherwise every stack was cropped against a scale built from single-column maxima. Positive and negative series pile away from zero separately. |
| Bug Fix | Chart per Value drew only the last series of a bar chart | The matplotlib node drew each y column with its own `axes.bar()` call at the same x positions and full width, so every series painted over the one before it and a two-column bar chart showed only the second — no error, just a quietly wrong chart. It now gains the same **Bar mode** setting as the two Plotly nodes: **group** offsets the series side by side, **stack** piles them up, and **overlay** keeps the old draw-on-top behaviour, which is still what you want with a single series or a transparent one. Grouping needs numbers to offset from, so the x values become tick labels over positions rather than matplotlib's own categories; rows are still taken one bar each, as the other kinds here already do. **stack** also teaches the shared Y scale about totals — a stacked bar reaches the row's sum, not its tallest column, and bounding the axis by the column maximum would have cropped every bar in the stack. Positive and negative series pile away from zero separately rather than cancelling out. The default is **group**, matching the Plotly nodes, so an existing bar chart that was hiding series starts showing all of them. |
| Feature | Report cards: a report inside the flow, and on a dashboard | **Viz > Report** is a markdown block that renders on the canvas and can be dropped on a dashboard page — which previously had no rich text at all. Its embeds name its **own wired inputs** (`![[a]]` is whatever is wired into input "a") and, since 0.1.8, **any node on the canvas by its label** as well. Where a name is both, the input wins — so unplugging a wire says so rather than quietly swapping that paragraph to another node of the same name. The two are not equivalent and the node's help says so: an input is a dependency the scheduler can see, so it orders the card after its source, re-runs when that source changes, and shows on the canvas what the report is built from; a label is none of those, which makes it handy for reaching a number across a big graph and unreliable under a partial run. Wire it up, rename the ports by forking the node, and the wires show on the canvas what the report is built from. **Right-click while editing the card** for an **Insert** submenu above the usual undo/cut/copy/paste: the card's own inputs first (unwired ones listed but disabled, so you can see they exist), then every node on the canvas that has produced something, duplicates greyed out. The embed syntax is the one thing about a report card you cannot guess, and a card has no room for the toolbar button a report page uses. The in-place editor also stops committing when the window merely loses activation — it used to commit on *any* focus loss, so opening the menu closed the editor out from under it and right-clicking just ended edit mode. Alt-tabbing away now leaves a half-typed note open rather than committing and closing it; clicking elsewhere in the app still commits, and Escape still cancels. It renders through the same engine as a report page, so a chart, a table, a number or a list reads the same wherever it appears, and charts are drawn to the card's actual width so widening the card widens them. **A report page can embed a report card**: `![[My Summary]]` on a page renders that card's *contents* — its prose, charts and tables — rather than reproducing its source markdown with the `![[a]]` still in it. The nested embeds are resolved against the card's own wired inputs, never the page's labels, so a card cannot start reaching across the graph the moment it is embedded, and everything after it on the page resolves as the page again. A card wired into another card nests the same way, with a depth limit. |
| Bug Fix | Card nodes with several inputs bunched their ports into one blob | A card node (chart, table, report, KPI, slicer, control) draws its ports in the 26px header, which is fine for the usual one-per-side but cannot hold more: the **Report card's four inputs came out 6px apart with an 11px pin**, overlapping each other by 5px. You could not tell which was which, and grabbing the one you wanted was a lottery. Ports now run down the card's edge at the same 20px rhythm an ordinary node's port rows already use, so the two kinds of node read the same. Pins also **float clear of the node** instead of being centred on its edge, where half of every one was buried under the card and read as part of the border rather than a thing to grab. They always **start in the header**, however many there are, so the first pin lands where a single-port card has always put it and a second input doesn't make the whole row jump into the body. The spacing never compresses: a node with twenty inputs simply runs its pins past the bottom of its card and onto the canvas, because squeezing them back into the available height is exactly how they came to overlap in the first place. A node that has outgrown its card can be collapsed instead — see below. |
| Bug Fix | Resizing a Control Template card raised an error | A card's size is stored as the node's own `width`/`height` params, but the resize grip was offered on card *kind* alone — so dragging the corner of a **Control Template**, which declares neither, raised `node 'Control Template' has no param 'width'` out of the mouse handler and left the drag half-applied. Two halves to the fix: the template now **declares** `width`/`height`, because it is meant to be resizable and its own comments always said it was — and cards only offer a grip when they have somewhere to store the result, so the same omission in a node you fork costs you a missing grip rather than a traceback. Every other built-in card is unaffected. The template's comments now say plainly what declaring those params buys you. |
| Feature | Floating port names | **Settings > Canvas > Show port names** floats each port's name beside its pin — inputs to the left of the node, outputs to the right, drawn as the same small pill a renamed reroute already uses, so it is one visual language rather than two similar-but-different ones. Card nodes have nowhere to print their port names, so a node with several inputs was previously a row of identical pins with only a tooltip to tell them apart. Off by default, and hidden when the canvas is zoomed out far enough to flatten the nodes, since the pins themselves aren't drawn at that distance. **Right-click any node for Show/Hide Port Names** to override the setting for that one node — useful for labelling the one hub node in a graph without turning names on everywhere. The override is remembered per node, saved with the project and undoable; toggling a node back hands it to the canvas-wide setting again rather than pinning it, so the global switch keeps working on everything nobody has singled out. Projects written before this open with every node following the setting. |
| UI | Settings pages are a two-column grid | Each Settings page is now laid out like the Properties panel — setting name on the left, control on the right, with bold group headings — instead of a vertical run of controls each followed by a paragraph of explanation. The Canvas page had grown to nine settings and needed scrolling to see them all; it now fits on one screen, and you can see at a glance what a page contains. The explanations move to each row's tooltip, which is where the Properties panel already keeps a param's description. The category list on the left is now a **tree**: each page's groups hang under it, and **selecting a group narrows the page to just that group's settings** — so the whole of Settings is visible at a glance and you are never shown more than you asked for. There are no heading rows inside a page; with the tree carrying the structure they said the same thing twice. Above it is a **search box** that filters every page at once — it matches a setting's name, its explanation *and* its group heading, so "muted" finds the colour-strength spinners and "snapping" finds the grid controls, and categories with no matches drop out of the list rather than being left to click into an empty page. The window opens wider so the grid never comes up with a horizontal scrollbar under it. Explanations are wrapped over several lines rather than one long one, because Qt treats a plain-text tooltip as a single unbreakable line and a paragraph-length hint ran off the edge of the screen. Nothing was removed and every control behaves as before. |
| Feature | Collapse a node's ports | A node with many inputs runs its pins past the bottom of its card by design, which is right while you are wiring it and noise once you are done. Click the **chevron in the node's header** — or right-click for **Collapse Ports** — and every pin gathers back into the header as one, with all the existing wires converging on it. Click again to fan them out. Nothing is disconnected: it is purely how the node is drawn, so the wires, the flow and the runs are untouched. Expanded by default, since a collapsed node hides which input is which; the collapsed pin's tooltip says how many ports are hidden and which one a dropped wire would land on, rather than pretending to be a bundle, and with port names showing it reads "4 inputs" rather than naming just the first — which implied the others weren't there. Saved with the project and undoable in one step, so a graph you tidied reopens tidy. Offered only on card nodes with more than one port a side — an ordinary node sizes its height from its port count and can never outgrow itself. |
| Bug Fix | Double-clicking a reroute opened its code | Double-clicking any other node's header renames it, but a reroute is all dot and no header, so it fell through to opening the reroute node's source — which is of no use to anyone. Double-clicking a reroute anywhere now renames it, which is the only thing about one worth editing: the name is the floating pill that appears above the dot, and an unnamed reroute stays deliberately labelless. |
| Feature | Report pages, and PDF export | A third kind of page beside Model and Dashboard. The **+** button now asks which you want; a report page is a markdown document on the left and a live preview of the printed result on the right. Anything the flow produced comes in **by name**: `![[Sales Chart]]` embeds that node's output, `![[Model\|scores]]` a particular port. What an embed becomes depends on what the node made — a matplotlib figure is placed as a picture, a DataFrame as a table (long ones cut with a note saying so, never silently), a number inline in your sentence. **A node that returns a string is inlined as markdown**, which is the interesting one: build headings, prose and tables in a Python Script node and the report writes itself from the data. That string is **dedented on the way in**, because it was built inside `run()` and so carries Python's own indentation on every line — and four leading spaces in markdown means *code block*, so a triple-quoted heading came out as literal text. Relative indentation is kept, so nested lists and deliberately indented code blocks are untouched. **Export PDF…** prints the same document the preview shows, so the export can't drift from what you were looking at. Embeds that don't resolve say so **on the page** and again when exporting, because a report gets handed to other people and a section that silently vanished is the worst outcome. An "Insert embed" menu lists the nodes that have actually produced something. Everything is ordinary page machinery: reports are saved with the project, renamed, recoloured, reordered, duplicated (body and all) and undone like dashboards, and typing is merged into sensible undo steps. Plotly charts need `kaleido` to appear in a report and say so if it's missing. First pass — page setup, headers/footers, forced page breaks and per-embed sizing are still to come. |
| Feature | Open a web-view node in your browser | Right-click a **Show Web View** / **Show Plotly** node — on the canvas or as a dashboard tile — for **Open in Browser**, and the page it is showing opens in your real browser. The card is a genuine Chromium view, so this isn't about capability, it's about room and about everything a browser has that a card on a canvas doesn't: the full screen, find-in-page, zoom, print, view-source and devtools, and a window you can leave open beside the app while you carry on editing the graph. The browser gets **exactly** the HTML the card renders — the coercion moved into one shared place so the two cannot drift — including a list of charts laid out on the node's own columns/rows grid, which finally gets the height it wants. The page is written to a file named after the node, so the browser tab says which node it came from and the file is yours to keep or send. **The tab keeps up with the graph**: that file is rewritten every time the node runs again, so change your data, re-run, and hit refresh — the browser shows what the canvas is showing. Nothing is handed to the desktop on a re-run, so it never steals focus or spawns a second tab, and only nodes you actually opened are kept up to date. A run that produces nothing renderable leaves the last good page alone rather than blanking the tab. The entry only appears when there's something to open, and a node that has been edited since its last run says so — the page is the last run's output, which is easy to forget once it's in a window of its own away from the STALE badge. |
| Bug Fix | A node needing a package you don't have no longer costs you the project | A node script is *executed* to read its `NODE`/`PARAMS` declarations, so an `import` at the top of the file runs whenever the node is loaded. If that package wasn't installed, opening a project containing such a node **failed outright** — the whole file refused to open over one node, which is exactly what happens when a project moves to another machine. That node now loads as a placeholder holding its code, its params, its label, its colour and its wiring, and the rest of the project opens normally; re-saving writes it back untouched, so nothing is lost. The node says what's missing and what to do about it, naming the package and pointing at **Manage Packages…**. Install it, hit **Apply** in the code editor on the unchanged code, and the node repairs itself in place — previously that was refused as "no changes to apply", leaving no way back. The same install hint is now attached to a `ModuleNotFoundError` raised *inside* `run()` too, and a skipped user node in the library says why it was skipped instead of only naming the file. Running was already safe (a bad import failed the one node, never the app) and still is. |
| Feature | Layers: bring to front, send to back | Overlapping cards and tiles can now be restacked instead of being stuck in the order they happened to be created. Right-click a node, a frame, or a dashboard tile for a **Layer** submenu — **Bring to Front**, **Bring Forward**, **Send Backward**, **Send to Back** — or use **Ctrl+]** / **Ctrl+[** and add Shift for all-the-way, matching Illustrator and Figma. Dashboard tiles gained a right-click menu for it, which they previously had none of. It works on a whole selection at once, which travels as a block so repeated presses walk a stack predictably rather than shuffling the selection against itself. Each kind stacks among its own: frames stay behind the wires and nodes in front of them, so raising a mixed selection raises each among its peers rather than lifting a backdrop over a card. One undo step per press, and the order is **saved with the project**, so a dashboard you arranged reopens arranged. New and pasted items land on top; duplicating a page carries its stacking to the copy; a maximized tile still covers the page whatever is stacked above it. Files written by earlier versions open in exactly the order they rendered in before. |
| Feature | A linked Table keeps its contents when you disconnect | A Table node fed by an input shows a *merge* — the input's columns refreshed on every run, your own columns stored in the node — but only your half was ever persisted, so cutting the wire collapsed the grid back to those few columns and threw the data away. Disconnecting now writes whatever the grid is showing into the table first, so the node carries the data from there on and runs standalone. Covers every way a link ends: deleting the wire, deleting the node upstream of it, and dragging the wire off or onto something else. It's part of the same undo step, so one Ctrl+Z puts the wire *and* the previous sheet back; the status bar names the tables it rewrote. Splitting the wire with a reroute isn't a disconnect and leaves the table linked, and an input that never ran is left alone rather than overwriting your columns with an empty merge. **Import input into table** still does the same thing on demand, without disconnecting. |
| Bug Fix | Resizing a linked Table blanked it | A linked Table's card shows the *merge* of upstream data with the user's own columns, but only the user's half is stored on the node — and any param change re-synced the grid from that stored half alone. So resizing the card (which writes `width`/`height`) emptied a populated table back to a blank 2×2 grid until the next run, as did editing a param in Properties or undoing. The grid now re-derives the merge whenever it re-syncs, on the canvas card and on a dashboard tile alike. Connecting an input whose data is already cached also fills the grid straight away instead of waiting for a run. |
| Feature | `date` param type | Node scripts can declare `{"type": "date"}` in `PARAMS` for a calendar picker in the properties panel, storing an ISO `YYYY-MM-DD` string. |
| Feature | Find and replace in the code editor | **Ctrl+F** opens a find strip under the code editor, **Ctrl+H** the same strip with replace fields. Every match in the file is highlighted as you type, with the current one picked out more strongly and an "n of m" counter beside the box; Enter or **F3** walks forward, Shift+Enter or **Shift+F3** back, both wrapping around the ends. Toggles for match case and whole words, Replace to swap the current match and step on, and All to replace everything in a single undo step. Opening with text selected seeds the search with it, Esc closes and clears the highlights, and switching to another node closes the bar rather than leaving highlights over a document that has been replaced. The shortcuts are scoped to the Code panel, so Ctrl+F on the canvas or in a spreadsheet is unaffected. |
| Feature | Click an error to copy it | Clicking the red error message under the code editor copies it to the clipboard — the full traceback when there is one, not just the line that fits in the footer. The label confirms with "Copied to clipboard." and puts the error back a moment later. Errors show a pointing-hand cursor and a "click to copy" tooltip carrying the whole traceback; ordinary messages like "Applied." are not clickable. |
| Feature | Reset settings and window layout | **Settings > General** gained two reset buttons. **Reset window layout** puts the Library, Properties, Code, Inspector and Log panels back where a fresh install has them — for when a panel has been dragged somewhere unrecoverable — without touching the window's size or position. **Reset all settings to defaults** clears every stored preference (everything on the Settings pages, the window layout, the AI assistant settings and the recent files list) and applies the defaults live, with no restart needed. Both confirm first, and neither touches your saved projects. An open Settings window is pulled back into sync afterwards rather than left showing the old values. |
| UI | Slicer draws radio buttons in single mode | A Slicer set to "single" selection now draws radio buttons instead of checkboxes, matching Power BI and Excel — a checkbox promises you can tick several, which single mode then silently undoes. Painting only: the selection is stored and reported exactly as before, and multi mode is unchanged. |
| UI | Clicking a slicer's label ticks it | Clicking anywhere on a slicer row now toggles it, in both multi and single mode, instead of only the 14px tick box itself — the label used to just select the row and look dead. |
| UI | Goto picker is sorted alphabetically | The **Goto** dropdown in a From node's properties lists Gotos alphabetically (case-insensitively) instead of in the order they happened to be dropped on the canvas, which was unusable once a graph had more than a few. |
| Bug Fix | Spreadsheet Enter was handled twice | Pressing Enter in an open cell editor was acted on by both the grid (moving the current cell down) and the editor's own commit, in that order — so the current cell moved out from under the editor before Qt committed it, and Qt logged `QAbstractItemView::commitData called with an editor that does not belong to this view` on every single cell edit. The editor now owns Enter while it's open, and the move-down happens after the commit, where it belonged. Affects every spreadsheet surface: the canvas Table card, the pop-out editor, and dashboard Table tiles. Enter with no editor open still steps down, and Shift+Enter still steps up. |
| Feature | Table tiles are editable spreadsheets | A Table node dropped on a dashboard page is now the node's actual spreadsheet rather than a read-only picture of its output (which is what 0.1.7 shipped). Everything the canvas card can do comes along: typing, formulas, column types, the header menus for inserting/deleting/renaming/sorting, Excel copy/paste, Ctrl+D fill-down, and a +Row/-Row/+Col/-Col/Fit toolbar. Each edit is one undoable step on the same undo stack, and it immediately re-runs the table and everything downstream of it, so the charts and KPIs beside it follow the number you just typed — the way a Slicer tick already does. Edits made anywhere else (the canvas card, an undo, a redo) show up in the tile straight away, and a table linked to an upstream input shows the same merged sheet the card does after a run. Combined with maximize, this gives you a full-page spreadsheet: drop a Table, hit ⛶, and the grid fills the window. Table tiles land bigger by default (560×360) and never show the STALE badge, since a grid you are typing into is input, not a stale render. |
| Feature | Maximize a dashboard tile | Double-click a tile's title bar — or click the ⛶ button that now sits at its right — to blow that visual up to fill the whole page; Esc, the same button, or another double-click brings it back. The maximized tile is pinned to the viewport, so it grows and shrinks with the window and its content grows with it: a Plotly chart re-lays out, a table shows more rows, a KPI number scales up. The Visuals panel steps aside for the extra width, zoom snaps to 100% so embedded widgets render at their natural resolution (your previous zoom and position come back on exit), and panning/zooming/dragging are parked until you leave. **Which tile is maximized is saved with the project**, so a page you left maximized reopens that way — and a dashboard you send someone opens looking the way you built it, full-screen pages included. It's an ordinary undoable edit like moving a tile, so Ctrl+Z restores the page, and duplicating a page carries the maximized tile to the copy. The tile's own position and size are never touched, so restoring always puts it back exactly where it was; deleting the tile exits cleanly, and undoing that delete brings it back maximized. Files written by earlier versions open unmaximized. Action Button tiles have nothing to enlarge and keep no button. |
| UI | Node colours are muted like frames | A custom node colour is now laid over the theme's card colours instead of painted raw, so picker colours come out muted rather than garish — the treatment frame headers and page tabs already use. Applies everywhere a node's colour shows: card body and header, the zoomed-out simplified card, note and Goto/From cards, and the minimap. The stored colour is unchanged, so existing projects keep their colours and just render calmer, and the colour picker still reopens on the colour you chose. |
| Feature | Colour muting strength is configurable | **Settings > Canvas > Custom colour strength** sets how much of a picked colour comes through, as two percentages: one for large surfaces (node card body, unselected page tab) and one for the smaller strip that stands out from it (node header, selected tab). Changes apply live across the canvas, minimap and page tabs, and persist across sessions. 100% paints the colour raw, i.e. no muting at all. |
