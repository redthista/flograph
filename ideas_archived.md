8. Reports — HTML export via Jinja (was ideas.md chunk B, "BIG ONE"). A *second* export target alongside the PDF one, not a replacement, agreed 2026-07-26. Why it was worth it: real CSS — `@page`, `@media print`, forced breaks, `page-break-inside: avoid` (keeping a chart off a page boundary, which Qt cannot express at all), running headers and footers with counters; web fonts, flexbox/grid; Plotly staying **interactive**; browser print-to-PDF for anything designed. Most of the groundwork already landed and is not part of the remaining cost: `core/html.py` (Qt-free coercion), `ui/browser.py` (writes a named page to a session temp dir and hands it to the desktop), `core/page_setup.py` (the geometry, with `page_css()` already emitting the `@page` rule), and `ui/report/html.py` (a rendered report as one self-contained HTML file, charts inlined as data URIs, animations kept as the GIF/WebP they arrived as). What is genuinely left is the **template**: Jinja, a stylesheet the user can replace plus a code node that injects CSS, `@media print`, running elements with counters, and keeping Plotly interactive rather than snapshotting it. Carries with it **B1, a preview that can show either target** (asked for 2026-08-12, after the first look at Save HTML): a target dropdown on the report toolbar — *Pages* (today's paged preview, what the PDF will be) and *Web* (a QWebEngineView of the exported HTML). The view itself is cheap since the app already embeds Chromium for the Plotly snapshotter, but it needs the template to exist first or it previews a page nobody would ship. Cost to be honest about: today the preview and the PDF are literally the same QTextDocument and cannot disagree; with a browser round trip the preview becomes an approximation and "open in browser" becomes the real preview. 0.1.9 narrowed the gap rather than closing it — the exported HTML now carries the page's own `@page` size and margins and measures its body to the same text column, so it prints sensibly from a browser, but it is one continuous page rather than a stack of sheets and always will be. One original argument has evaporated: "and it needs no kaleido" stopped being true when 0.1.8 started snapshotting Plotly through the embedded Chromium, so the PDF path needs no extra library either — the CSS and pagination arguments stand on their own, this is just a smaller win than it looked. Shelved 2026-08-12.
9. Drop a node onto a wire to splice it in; onto a node to replace it (was ideas.md G4). Shipped 2026-08-25. Dragging from the library now aims: the wire under the node lights green (`ConnectionItem.set_drop_hint`) when letting go would splice, a dashed ring shows around a node that would be replaced (`NodeItem.set_drop_hint`, one child item rather than a pen in every `_paint_*`); `drop_target_at` only ever names a target the drop will fully satisfy, so the highlight cannot lie. Splice is all-or-nothing — both ends must find compatible ports or it falls back to a plain add. Replace remaps wires name-first (reserved across all wires before fallbacks run, so an early wire cannot steal another's port), cuts what has no home (with the linked-Table snapshot the delete path uses), retargets order edges for free, carries `label_override` and the old position, refuses locked nodes, and is one undo step. `Alt` drops past all of it. Tests in `tests/test_drop_splice_replace.py`.
10. Click a node's name in the statistics window to jump to it (was ideas.md G5). Shipped 2026-08-25. Every name in the window is live — both tables and the timeline's gutter. Table cells carry the node id in `Qt.UserRole` (labels can lie; ids cannot), a click anywhere in a row reveals, and `RunTimeline` factors its row layout into `_row_geometry` so `paintEvent` and hit-testing cannot disagree about where a click lands — only the name gutter is clickable, since the bars answer "when", not "which", with a pointing-hand cursor over names to say so. The tabs take an optional `reveal` callback and emit `StatsWindow.reveal_requested`; `MainWindow._show_stats` wires that once to `_go_to_node`, which now also steps a dashboard or report page aside first, on the same reasoning as Find Node: jumping over a hidden canvas looks like nothing happened. The jump reuses `NodeGraphView.go_to_node` whole — select, centre, zoom back in from beyond the LOD smudge — so a name clicked here behaves exactly like a hit there, and a node deleted since an older run stays silent rather than erroring.
11. Scroll the canvas when a connection is dragged to its edge (was ideas.md G3, from Stu via KNIME). Shipped 2026-08-25. Holding whatever is being dragged against a viewport border now pans the canvas that way until the destination arrives — a wire's free end, a node, a multi-selection, a frame with its contents — no letting go, no panning, no starting over. The scene announces a canvas drag (`NodeGraphScene.canvas_drag_changed`, with `wire_drag_active` / `group_drag_active` / `canvas_drag_active` to read it; group drags count nesting depth so commit's nothing-moved early return can never strand the announcement), and the view runs a tick timer for the duration: each tick asks `edge_scroll_delta` — a pure function of viewport rect and cursor, band per axis, faster the deeper into the band — pans by it through `scroll_by` (the same translate math as a middle-drag pan), then re-aims what is in hand. A wire re-feeds the cursor's post-pan scene position into `update_wire_drag`; a dragged selection gets `_ride_selection`, which sends the view a synthetic mouse move through the ordinary event path — Qt anchors movable items to press position plus total cursor travel, so nudging items directly would be clobbered (and snap back) by the next real move, while a synthetic move lets Qt redo that arithmetic with post-pan coordinates: snapping, carried frame contents and group commits all behave exactly as if the mouse had carried the selection there. The timer also stops itself if it ever fires without a drag under it, so nothing can strand it scrolling forever. Frame pins are real PortItems and drag-detach reuses begin_wire_drag, so collapsed frames and grabbed wires edge-scroll without a line of their own.
12. The property panel's column pickers (was ideas.md chunk H, from Stu). Shipped 2026-08-20, in two commits (`a4752b6` the stay-open menu, `d46d930` the tick list). A `columns` param that takes several columns built its ticks into a plain `QMenu`, which closes on every pick — choosing six of eight meant opening the picker six times, each time from the top of the list. The multi menu now **stays up while you tick**, mouse and keyboard alike (a `_ColumnsMenu` that keeps itself open while any action carrying `_STAYS_OPEN` triggers), with **Select all** and **Select none** at its head for the two cases that are one click rather than eight; `_set_columns` re-ticks the still-visible entries in place, since nothing rebuilds them until the menu is next opened. A single-column param is unchanged — one pick is the whole interaction there, so it still closes on choosing — and each tick is its own undo step, because ticking six in a row is what the menu is for and one Ctrl+Z taking all six back would be a surprise. The second half: Rename Columns' `mapping` param and Expression's box are free text, so neither could use the picker at all and getting a name right meant flicking to a table view to copy it. Each gained a ▾ button listing `upstream_columns()`, and what clicking does follows what a line *means* in that box: **Rename takes one mapping per line, so its picker is ticks** — tick writes `region = ` with the caret after it ready for the new name, untick deletes the line again (read back off the text each open, so hand-edits un-tick themselves), via `"insert_columns": "mapping"` on the text param; **an Expression names several columns on one line**, so there the name inserts at the cursor and the menu closes (`"inline"`) — or starts a new line at the end when the caret was never placed, position 0 being where the widget was built rather than a choice. Any node script can ask for either with `insert_columns` on a text param. Tests: `tests/test_column_picker_ux.py`, `tests/test_column_suggestions.py`.
13. Nodes and frames that run only when asked (was ideas.md J1 + J2). Shipped 2026-08-25, one commit (`c4f1552`). A `manual` flag on `NodeInstance` (beside `active`/`locked`/`frozen`, right-click ▸ Run only when asked) takes a node out of every run that does not name it: Run All walks past it and so does the re-run a moved slider sets off, while Run To This Node, Run Selected and an Action Button naming it still fire. Not a third spelling of deactivate — a manual node **holds its place and whatever it last produced stays available downstream**, like a frozen value, so the dashboard under an expensive query keeps working off the last answer; only a manual node that has produced nothing yet skips the branch below, there being no input to run on. It wears a play triangle beside its padlock marks, the statistics window counts what a run held back under its own heading, and setting or clearing it dirties nothing — unlike releasing a pin — so taking a node off manual never re-runs it behind your back. The frame-level counterparts land with it: **Disable frame** takes everything inside out of every run along with what they feed; **Run frame only when asked** holds a stage back until its own ▶. The flag belongs to the *frame*, not to whichever nodes were inside when it was set — a node dragged in afterwards is held too, one dragged out runs normally, and membership is worked out afresh each run by the same containment rule that decides what dragging carries (so it reaches into folded frames). A node's own flag stays independent of its frame's, each toggle is one undo step, and nothing is dirtied or evicted from the cache.
14. Pan by holding right-click (was ideas.md G1) — built, tried, taken back out. Attempted 2026-08-25 and reverted the same day at Dan's request, after trying it for real. What shipped first was a threshold design: a right-press held for judgement in `ZoomPanGraphicsView`, past a few pixels of travel it became a pan and armed `_suppress_context` to swallow the menu Qt synthesizes from its release. Two lessons from putting it in front of someone: **the platform matters** — on his desktop Qt synthesizes the context menu from the right-button *press*, so the menu won every time before the threshold could; the fix (capture the press-time menu event while pending, re-issue it manually on release if the gesture stayed a click, swallow it if not) was designed but never needed. And **the shape of the setting was wrong**: he had expected a picker of pan buttons (left/middle/right), not a toggle — left would have collided with node-dragging and rubber-band selection and needed its own decision. Rather than grow it, he changed direction entirely: what he actually wanted was visible scroll bars. That shipped instead — **Settings › Canvas › Display › Show scroll bars**, `ZoomPanGraphicsView.set_scrollbars_enabled()` flipping both axes between `ScrollBarAlwaysOff` and `ScrollBarAsNeeded`, pushed to the main view and every dashboard view (`canvas/scrollbars`, off by default). G1 stays here as declined-by-user rather than open: if it ever comes back, start from the press-time menu lesson above.
