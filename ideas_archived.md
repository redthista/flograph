6. Manual apply mode for tables and controls. A per-node (or global) toggle switching a Table / slicer / input control between re-running downstream on every edit (today's behaviour, now coalesced into one run per burst — 0.1.8) and only running when an **Apply** button is clicked. For flows heavy enough that no amount of debouncing helps: batch a dozen edits, then commit once. Mechanically small — the SetParamCommand already dirties the subgraph whether or not anything runs, so it is a param, a button that lights when there are edits the flow has not seen, and an early return in `_on_dashboard_sheet_edited`. The open question is the badge: amber STALE currently means "you changed something, run when ready", but under manual apply it becomes that table's normal working state and would need to read as an invitation to click Apply rather than as a warning. Shelved 2026-08-03 — revisit if the 300ms coalescing turns out not to be enough.
7. Reports — the rest of pass 1 (was ideas.md chunk A). Pass 1 shipped and 0.1.9 finished the page-geometry half (page setup, running headers/footers, forced breaks, per-embed `width=`, a fenced ` ```columns ` block, Export PDF / Open in Browser from a report card). What was left when this was shelved, all small and independent: **alignment** of a sized embed — centring an image means setting the *block's* alignment after the document is built, a different job from sizing; **`![[chart|fit]]`** — shrink a chart into the space left on the page rather than letting it start a new one and leave a gap (sketch: after `setHtml`, use `documentLayout().blockBoundingRect()` for each image block's `y`, compute `remaining = body_height - (y % body_height)`, and if the image is taller than that but shorter than a whole page, scale and lay out again, twice at most — opt-in per embed, never global, because it makes charts silently different sizes on different pages); **balanced columns** (Qt fills each cell independently, so unequal content ends ragged at the bottom — fine for text-beside-a-chart, wrong for two columns of prose; needs the CSS target, see 8); **a Report Text node** so prose can be templated from data without hand-writing a Python Script node; **letting a report page embed a report card** (cards exist and are tileable, pages cannot embed one); **headless export** of every report in a project from the CLI; and **docx export?**. Shelved 2026-08-12.
8. Reports — HTML export via Jinja (was ideas.md chunk B, "BIG ONE"). A *second* export target alongside the PDF one, not a replacement, agreed 2026-07-26. Why it was worth it: real CSS — `@page`, `@media print`, forced breaks, `page-break-inside: avoid` (keeping a chart off a page boundary, which Qt cannot express at all), running headers and footers with counters; web fonts, flexbox/grid; Plotly staying **interactive**; browser print-to-PDF for anything designed. Most of the groundwork already landed and is not part of the remaining cost: `core/html.py` (Qt-free coercion), `ui/browser.py` (writes a named page to a session temp dir and hands it to the desktop), `core/page_setup.py` (the geometry, with `page_css()` already emitting the `@page` rule), and `ui/report/html.py` (a rendered report as one self-contained HTML file, charts inlined as data URIs, animations kept as the GIF/WebP they arrived as). What is genuinely left is the **template**: Jinja, a stylesheet the user can replace plus a code node that injects CSS, `@media print`, running elements with counters, and keeping Plotly interactive rather than snapshotting it. Carries with it **B1, a preview that can show either target** (asked for 2026-08-12, after the first look at Save HTML): a target dropdown on the report toolbar — *Pages* (today's paged preview, what the PDF will be) and *Web* (a QWebEngineView of the exported HTML). The view itself is cheap since the app already embeds Chromium for the Plotly snapshotter, but it needs the template to exist first or it previews a page nobody would ship. Cost to be honest about: today the preview and the PDF are literally the same QTextDocument and cannot disagree; with a browser round trip the preview becomes an approximation and "open in browser" becomes the real preview. 0.1.9 narrowed the gap rather than closing it — the exported HTML now carries the page's own `@page` size and margins and measures its body to the same text column, so it prints sensibly from a browser, but it is one continuous page rather than a stack of sheets and always will be. One original argument has evaporated: "and it needs no kaleido" stopped being true when 0.1.8 started snapshotting Plotly through the embedded Chromium, so the PDF path needs no extra library either — the CSS and pagination arguments stand on their own, this is just a smaller win than it looked. Shelved 2026-08-12.
14. Pan by holding right-click (was ideas.md G1) — built, tried, taken back out. Attempted 2026-08-25 and reverted the same day at Dan's request, after trying it for real. What shipped first was a threshold design: a right-press held for judgement in `ZoomPanGraphicsView`, past a few pixels of travel it became a pan and armed `_suppress_context` to swallow the menu Qt synthesizes from its release. Two lessons from putting it in front of someone: **the platform matters** — on his desktop Qt synthesizes the context menu from the right-button *press*, so the menu won every time before the threshold could; the fix (capture the press-time menu event while pending, re-issue it manually on release if the gesture stayed a click, swallow it if not) was designed but never needed. And **the shape of the setting was wrong**: he had expected a picker of pan buttons (left/middle/right), not a toggle — left would have collided with node-dragging and rubber-band selection and needed its own decision. Rather than grow it, he changed direction entirely: what he actually wanted was visible scroll bars. That shipped instead — **Settings › Canvas › Display › Show scroll bars**, `ZoomPanGraphicsView.set_scrollbars_enabled()` flipping both axes between `ScrollBarAlwaysOff` and `ScrollBarAsNeeded`, pushed to the main view and every dashboard view (`canvas/scrollbars`, off by default). G1 stays here as declined-by-user rather than open: if it ever comes back, start from the press-time menu lesson above.
